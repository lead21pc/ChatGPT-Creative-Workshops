# FWE Source Contract

This contract defines source roles and limits the claims each role can support. [CI](../controls/FWE_CI_v0.1.md) determines the assigned task, creative authority, protected state, and permissible conclusions. The [Router](../controls/FWE_ROUTER_v0.1.md) applies this contract when handling sources for a delegated slice. The user or the established target-system authority accepts canon.

## Roles and limits of use

| Role | Use |
|---|---|
| User-supplied fictional context | Use it in the role assigned by the request, such as a working premise, constraint, task-local state, example, reference, or design material. Apply it only within the assigned scope. |
| Target-project current source | Use material actually read and designated or verified as current for the relevant project, scope, status, and authority. Assigning one source to a task slice does not confer equivalent authority on other sources. |
| Attached or reference material | Use it for reference, comparison, or the assigned input role. A claim about current state requires evidence establishing the material's role as a current source. |
| Temporary premise | Use it as an assumption for the specified turn, test, or scope. Outside that scope, return to established state. |
| Branch | Use the branch's premises and state for the requested development. Keep branch state separate until the authorized party accepts it. |
| Proposal | Offer it for consideration by the user or the target system. Keep it in proposal status until accepted. |
| Protected unknown | Preserve the unknown when using established facts. If CI receives a design request for that specific gap, develop alternatives and keep their proposal status. |
| Historical, superseded, or provenance material | Use it for history, comparison, provenance, or explicitly authorized recovery. If a current source is missing, keep conclusions about current state conditional or unresolved. |
| Cross-project inspiration | Extract the mechanism or seed assigned as inspiration and develop it under the target system's ontology, state, and constraints. Keep the source system's lore, authority, ontology, and dependencies within that system. |

A role applies to the material and claim at issue. Establish it from the user's assignment or evidence of current authority in the target system. Presence, filename, folder, recency, and detail do not by themselves confer authority. Base source-dependent conclusions only on material that was accessible and actually read. Material generated by FWE remains working material until the target authority accepts it. Each project retains its own sources of truth.

## Source sufficiency and missing sources

- Assess sufficiency for the specific claim and task slice. An excerpt may suffice for that slice. Limit the conclusion and any claim about what was checked to the material actually read.
- If a decisive source is missing, including when it is inaccessible, its authority is unclear, or its content is insufficient, make dependent work conditional, limit it, or stop it. Continue independent work when sufficiently supported. Keep reference and historical material in their assigned roles.
- When CI grants creative authority over a gap, invention is allowed without a prior source. When CI protects an unknown, preserve it. The absence of a source does not establish that an unresolved claim is false or grant permission to fill the gap.
