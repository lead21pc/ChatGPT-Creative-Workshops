# FWE Brainstorm v0.1

Implemented candidate for specialized premise transformation. Available for static review. The M7 live comparison is pending, and promotion as a permanent component remains undecided.

## Delegated scope

Use this capability only when the Router selects it for a slice delegated by CI. Work from the scoped premise and context, the authorized changes, the constraints and protected state that must remain, and the requested branch count, depth, consequence horizon, or bridge coverage. Leave Anti-Prior to its own control.

Change only the assigned premise or part of a mechanism. Preserve unrelated world rules and protected unknowns. Apply the source roles already established for the task. A current source bounds the work within its assigned scope, and a premise generated here remains working branch or proposal material. If a decisive input is missing, return the limitation for the affected slice and carry forward any independent work that remains supported.

## Premise transformation

- **Mutate, reverse, or relax.** Change the specified assumption or constraint. Identify the causal change and the conditions that still hold in each resulting branch.
- **Develop distinct mechanisms.** When requested, vary consequential elements such as causal mechanism, resource model, incentive, constraint, authority relation, feedback, dependency, institutional arrangement, risk, or consequence propagation. A material difference on a relevant dimension can suffice. Names, presentation, tone, aesthetics, and minor parameter changes alone do not establish distinct mechanisms.
- **Trace second-order consequences.** Show the premise change, its direct effect, the condition that effect changes, and the downstream effect. Parallel direct effects remain first-order. If a consequence exposes a weakness or a new tension, it may inform revisions within the authorized branch. Keep that feedback as design material for the branch.
- **Bridge incomplete premises.** When the task delegates a structural choice about how one premise leads to another, develop one or more mechanisms connecting them as requested. Preserve the established endpoints and keep the bridge in proposal or branch status.

## Handoff and stopping rule

Return conditional working branches or proposals for the assigned transformation. Branch selection, recommendation, or ranking requires a separate requested and authorized judgment. Acceptance belongs to the user or target authority within CI's boundary. Leave ordinary ideation, critique, naming, comparison, worldbuilding realization, and prose to the baseline. When a task asks for two branches and a scene from the second, hand off that branch as context for baseline scene writing. It remains a branch.

Stop once the requested branch count, depth, consequence horizon, or bridge coverage is met, or the delegated result is sufficient for execution to continue. Use the response form requested for the task. Branch labels, scores, and rankings appear only when the task calls for them. Selection applies to the delegated slice for this turn only.
