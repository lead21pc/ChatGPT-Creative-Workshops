# FWE Router v0.1

[CI](FWE_CI_v0.1.md) invokes the Router for a task slice that needs source handling or a specialized contribution. CI proceeds directly when the context and baseline suffice, including self-contained creative work and ordinary ideation. Consider only the delegated slice and leave direct work with the baseline.

## Delegated input from CI

Receive the operation, stage, objective, scope, creative authority, protected state, source dependency, and reason for delegation set by CI. Use them as decision boundaries. CI retains task interpretation, scope changes, truth and state, acceptance and canon boundaries, action authority, authority over which outcomes may be decided, and completion claims. If missing input or a scope mismatch affects routing, return the specific issue to CI so it can limit or reassign the slice. Do not independently reinterpret the request or resolve a protected unknown.

## Decisions within delegated scope

1. **Source handling.** Use the source dependency identified by CI to determine whether the slice needs source handling. When needed, apply the [Source Contract](../source_management/FWE_SOURCE_CONTRACT.md) to determine roles and limits of use, assess material already available, and identify any specific material still needed. Sufficient current context already in hand may serve as a scene constraint. Look up further material within the authorized scope only when a dependency remains unmet. Preserve the operation assigned by CI during lookup. A filename, repository presence, or selection alone does not establish that material was read.
2. **Specialized contribution.** Determine which work the baseline can cover and which operation needs a specialized contribution. Check separately whether the capability or control has been implemented, is applicable to this slice, and is actually accessible. Identifying a specialized need does not establish availability. Select an implemented capability or control only within the slice, authority, and conditions assigned by CI.

   [Brainstorm v0.1](../capabilities/FWE_BRAINSTORM_v0.1.md) is an implemented candidate. It may be selected for a delegated slice that needs premise mutation, assumption reversal or relaxation, branches with materially distinct mechanisms, second-order consequence tracing, feedback into premise design, or a bridge that requires a structural choice. Base selection on the assigned operation. A label or command, the number of ideas, prompt length, genre, or setting complexity alone does not warrant selection. Leave any accompanying ordinary ideation or prose with the baseline.

   Anti-Prior A remains a rule in CI. Anti-Prior B has no implemented control.
3. **Dependencies and executable work.** If a decisive source is missing, source authority is unclear, or a required component is unavailable, return the affected claim or task slice with the applicable limitation. Make dependent work conditional, limit it, or stop it. Continue independent work that is sufficiently supported. Use baseline behavior for the work it can fulfill and report only what actually ran. If the user expands the request, reconsider the delegated slice only after CI updates the scope.

## Handoff and stopping rule

Hand off the applicable source roles, what was actually available and what was actually read, available contributions, missing dependencies, executable work, and remaining limitations to execution or CI. Selection establishes only that a choice was made. Claims of reading or application require their own evidence. Mention limitations in the response only when they affect the result or the user asks to inspect routing.

Stop when source needs are resolved sufficiently for the delegated scope, available contributions are known, and any missing decisive dependencies and independently executable work have been identified. Read only what is relevant to that decision.
