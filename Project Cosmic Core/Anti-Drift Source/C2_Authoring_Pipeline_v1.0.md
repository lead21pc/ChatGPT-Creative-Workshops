# C2 — Authoring Pipeline v1.0

> Status: ACTIVE
> Type: PROCEDURAL AUTHORING CONTROL
> Boundary: Not an Anti-Drift overlay, Router, canon, source authority, truth-status authority, state store, or actor-outcome selector.

## Activation and stop point

Use this procedure when the request calls for seed extraction, functional abstraction, implementation stripping, material primitive decomposition, C2 candidate comparison, application/localization within C2, or an implementation proposal. Keyword occurrence alone is insufficient. Ordinary lookup, audit, canon externalization, simulation, and discussion use it only for a requested transformation included in that work.

Identify the requested transformation and stop point before proceeding:

| Requested operation | Stop at |
| --- | --- |
| Extract a seed, abstract function, or strip implementation | Functional seed |
| Decompose material primitives | Material primitives |
| Compare a candidate with current C2 | Supported comparison |
| Apply/localize in C2 or propose implementation | Bounded local proposal |

Proceed from the relevant input basis to the needed seed, primitives, current-state cross-check, or proposal. Skip already-satisfied transformations. Use the CI's rules for clarification, scope, and truth status. Do not continue into redesign, integration, implementation, simulation, second-order consequences, or alternatives unless the requested operation requires them.

## Seed and primitives

Separate new input, current C2 evidence, and external comparison material by their supported roles. Extract the functional or causal core while stripping nonessential implementation. Preserve intent and decisive relations. Do not reverse-define the seed from a later implementation.

Extract only material components such as function, actor/entity role, condition, state or transition, information or causal relation, input/output, authority, capability, constraint, resource, interface, or failure path. Use the necessary components and keep unsupported relations UNKNOWN or conditional. Require no complete schema.

## Early Router handoff

Before the first step that materially depends on current C2 state, declare the information need to the Router. This can precede seed extraction or decomposition, or occur during comparison or proposal composition. Repeat the handoff if a later step introduces a new material current-state need. Resume only the transformation supported by the resulting route.

The Router owns discovery, identity, admission, controlling owners, authority, loading, reconciliation, Anti-Drift selection, and source block/partial decisions. Keep the request scoped to the information needed. Use applicable controls through the Router. The Pipeline cannot waive the CI's Router entry requirement, select source authority, or substitute for a blocked premise.

## Comparison and proposal

Compare only against relevant routed current constraints. Report supported compatibility, conflict, and unresolved dependencies. Comparison supplies no authorization for repair.

Compose a proposed local implementation only when requested. Preserve the seed and current invariants. Do not redesign current C2 to accommodate the candidate. Missing decisive facts remain subject to the Router's block. A labeled design assumption can support a conditional proposal without standing in for a current fact. Compatibility and a completed proposal confer no acceptance or canon change.
