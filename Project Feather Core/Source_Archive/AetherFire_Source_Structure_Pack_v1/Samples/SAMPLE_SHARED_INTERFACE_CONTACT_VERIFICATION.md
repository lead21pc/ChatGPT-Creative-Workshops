## Example body

### 0. Interface contract

```text
MUTUAL DISTRUST / LIMITED CONTACT
→ CONTROLLED CONTACT INTERFACE
→ VERIFICATION
→ RESTRICTED ACCESS OR DENIAL
→ HANDOFF TO THE NEXT AUTHORIZED CHANNEL
```

The interface describes what the parties must exchange or verify. It does not require identical sensors, laws, magic systems, or internal security organizations.

### 1. Common requirement

Participants need a way to:

- establish the delegation's claimed identity and mandate;
- control weapons / dangerous capabilities at the contact boundary;
- distinguish temporary interface access from entry into the interior;
- maintain an authenticated communication route;
- record the result of verification;
- escalate to a deeper diplomatic channel only after required checks.

### 2. Endpoint variation

**AetherFire example implementation:** may use magic-technology identity and access tooling.

**Foreign polity example implementation:** may use ritual, formation, cultivation, legal witnesses, relic verification, or another internally coherent mechanism.

```text
SAME INTERFACE FUNCTION
!= SAME IMPLEMENTATION
```

### 3. Non-claims

The existence of this interface would not by itself establish:

- a permanent DMZ;
- identical border law;
- technological dependence on AetherFire;
- common origin of verification systems;
- that every foreign contact uses the same procedure.
