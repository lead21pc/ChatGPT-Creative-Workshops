# The Kingdom → AetherFire Migration Worksheet

> **Working status:** `PROPOSAL TOOL / NON-RUNTIME`
> **Canon effect:** NONE.
> **Input rule:** The Kingdom material is historical/reference seed unless a separate current decision restores a bounded claim.

## 1. Unit of migration

Do not migrate a file as a package.

Use:

```text
LEGACY FILE
→ claims / functions / requirements
→ decomposition
→ owner proposal
```

## 2. Classification

Every extracted item should receive one primary disposition:

| Class | Meaning |
| --- | --- |
| `COMMON_REQUIREMENT` | many actors can face the same problem |
| `SHARED_INTERFACE` | interaction contract across owners |
| `POLITY_IMPLEMENTATION` | one polity's local solution |
| `SPECIALIZED_CAPABILITY` | deep capability deserving a dedicated owner |
| `LOST_HISTORICAL_CANDIDATE` | over-ceiling or ontology-displaced legacy capability; still only a candidate |
| `METHOD_CONTROL` | worldbuilding / simulation / anti-drift method, not lore |
| `ARCHIVE_ONLY` | provenance with no current migration target |
| `DROP` | not useful or incompatible |
