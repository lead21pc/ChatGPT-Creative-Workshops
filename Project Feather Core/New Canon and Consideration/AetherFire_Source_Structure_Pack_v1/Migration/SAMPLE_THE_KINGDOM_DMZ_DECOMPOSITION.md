# SAMPLE ONLY — Decomposing The Kingdom DMZ / Delegation Material

> **Sample status:** `NON-CANON / NON-RUNTIME`
> **Purpose:** demonstrate migration by function instead of copying the legacy implementation.
> **No canon claim:** none of the candidate implementations below are admitted by this sample.

## 1. Legacy package

The legacy material combines:

- a controlled external contact zone;
- initial verification delegation;
- restricted entry;
- communication handoff;
- security screening;
- host-side transport;
- later diplomatic escalation.

Treating this as one inherited “technology” would over-combine process, sovereignty, security, infrastructure, and diplomacy.

## 2. Abstract requirements

### COMMON_REQUIREMENT

```text
LOW TRUST
+ NEED FOR CONTACT
+ SOVEREIGNTY RISK
→ CONTROLLED CONTACT PROCEDURE
```

Common needs may include:

- prove identity;
- prove mandate;
- screen dangerous capabilities;
- create a secure communication path;
- keep initial contact physically/logically separated from the interior;
- preserve evidence of what was verified;
- decide whether deeper access is allowed.

These requirements can independently appear in multiple states.

## 3. Proposed shared interface

### SHARED_INTERFACE candidate

`Interstate Contact & Verification`

Controls only:

- recognized entry state;
- required handoff information;
- verification result;
- temporary access state;
- escalation / denial state.

It should not control:

- AF's internal sensor stack;
- RF's internal formations or cultivation checks;
- ML's ritual or religious authority;
- any polity's full border law.

## 4. Possible local implementations

### POLITY_IMPLEMENTATION — AetherFire candidate

Could use AetherFire-specific magic-technology integration.

Still requires separate decisions for:

- credential source;
- sensor architecture;
- escort authority;
- data retention;
- appeal / diplomatic override;
- emergency containment.

### POLITY_IMPLEMENTATION — another polity candidate

Could solve the same functions with a different ontology.

No foreign implementation is inferred by this sample.

## 5. Lost-civilization test

A normal controlled contact zone is **not** a lost-civilization candidate.

Only a bounded legacy mechanism should move into that bucket if it exceeds the present setting's accepted ceiling, for example a hypothetical verification device that establishes truth with near-absolute reliability.

Even then:

```text
TOO STRONG FOR CURRENT POLITY
→ LOST-HISTORICAL CANDIDATE

NOT
→ AUTOMATIC LOST CIVILIZATION CANON
```

## 6. Result

The legacy “DMZ + delegation” package decomposes into:

```text
COMMON REQUIREMENT
+ SHARED INTERFACE
+ MULTIPLE POSSIBLE LOCAL IMPLEMENTATIONS
+ OPTIONAL OVER-CEILING REMNANT CANDIDATES
```

This preserves the useful procedural logic without making AetherFire the owner of a universal diplomatic technology stack.
