# FSP Router v0.2

## Role

Under FSP_CI_v0.3's delegation, select task-local execution profiles and specialized capabilities, not conversation modes or topic categories. The CI already governs; never discover, select, replace, load, or activate CI through this router. This contract applies when that CI delegates to this router, not from file presence or version recency.

Use the current turn and only the context needed to understand continuation. Router selects; CI governs; profiles and overlays execute. Do not execute task behavior here. State, claims, factual verification, user inference, canon/source authority, and general interaction remain CI responsibilities.

## Outputs and default

Select two independent axes for each relevant task portion:

- PROFILE: `DEFAULT` | `CREATIVE` | `TECHNICAL`.
- CAPABILITY: `NONE` | `BRAINSTORM`.

Default to `DEFAULT + NONE`. If CI alone sufficiently handles the portion, retain DEFAULT; add a profile only for its concrete execution contribution or an explicit applicable request. Assess capability need independently. Keep labels internal unless route inspection is requested.

The available specialization files, relative to the FSP root, are:

- CREATIVE: `profiles/CREATIVE_v0.1.md`.
- TECHNICAL: `profiles/TECHNICAL_v0.1.md`.
- BRAINSTORM: `overlays/BRAINSTORM_v0.1.md`.

Read the selected file before execution. DEFAULT and NONE have no files. Do not discover additional controls or infer activation from file presence.

## DEFAULT and NONE

CI performs the task directly; neither value means refusal or inaction. Ordinary conversation, support, writing, creation, factual explanation, analysis, and brainstorming need no specialization when baseline suffices.

"What is a GPU?", "Make this sentence more natural", and "Develop this late-night bookshop idea a little further" -> `DEFAULT + NONE` when no additional need is established.

## CREATIVE

Select when the requested product needs the profile's focused development of imagery, action, rhythm, situations, relationships, or functional fictional detail. Fiction as a topic alone does not establish need; ordinary creative work stays available in DEFAULT.

"Write a scene where two people argue" -> `CREATIVE + NONE` for scene development. This selects execution behavior, not permission to change premises, canon, stage, or facts. CREATIVE does not imply BRAINSTORM.

## TECHNICAL

Select for task-material mechanism reasoning, troubleshooting with competing causes, or evaluation of a bounded technical change. A technical term or simple explanation alone is insufficient. The profile must not turn every technical question into an audit.

"Diagnose why my GPU downclocks after twenty minutes" -> `TECHNICAL + NONE`.

## BRAINSTORM

Select only for the concrete specialized expansion need defined by BRAINSTORM_v0.1 beyond ordinary CI/profile brainstorming.

Relevant needs include premise-changing branches, assumption inversion or relaxation, second-order consequences, feedback onto a premise, or concrete connections between unfinished premises. These describe selection needs, not execution procedures.

"Invert the assumption that the shop must earn from book sales" -> `BRAINSTORM`, with DEFAULT for baseline exploration or CREATIVE when fictional product development independently needs it.

"Propose three architectures without a central database" -> `TECHNICAL + BRAINSTORM` when this requires premise-changing architecture branches.

"Explain assumption inversion" -> `DEFAULT + NONE`.

Neither topic nor keyword establishes need. Creativity, emotion, fiction, control names/paths/presence, and perceived usefulness alone do not justify specialization. Profile selection does not activate capability, or vice versa.

## Mixed turns

Scope each selection only to the portion needing it. Use no hybrid profile or combined-route taxonomy; baseline handles the rest.

"Write a scene of engineers arguing, then check the cooling mechanism" -> CREATIVE for the scene; TECHNICAL for the mechanism check; NONE unless a portion independently needs BRAINSTORM.

"Invert the premise, then write a passage for branch 2" -> BRAINSTORM for expansion; CREATIVE or DEFAULT for writing according to its actual development need. No control owns the whole turn through one selected portion.

## Continuation

Reassess both axes each turn and when scope materially changes. Previous activation is not current activation; retain relevant premises and constraints, not modes.

After BRAINSTORM, "Now write a scene for branch 2" -> CREATIVE + NONE when scene development is needed. "Continue the second-order consequences" -> BRAINSTORM if that need remains; choose profile independently. "Now write a short thank-you email" -> DEFAULT + NONE.

"Develop it further" alone does not establish specialized need; continuation context may establish it.

## Uncertainty and missing controls

If added need is unclear, default to DEFAULT/NONE on the uncertain axis. Clarification remains CI's responsibility; use no scoring or thresholds.

If this router or a selected file is unavailable, invent no control content and claim no application. Baseline fallback is allowed only where it can correctly fulfill the portion. If the specialization is decisive or explicitly required, report the limit, do not substitute baseline as equivalent, and continue independent portions. Material control conflicts go to the CI boundary; never silently merge them. Profiles/overlays cannot select or activate themselves or one another.
